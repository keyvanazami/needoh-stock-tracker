# Phase 1 test server — instructor notes

Source for the server students get as a binary. Ship `dist/xchg-server.jar`;
keep `src/` here.

## Build

```bash
./build.sh            # -> dist/xchg-server.jar, then runs the CRC self-test
```

JDK 17+ and nothing else: no Maven, no Gradle, no network, no third-party jars.
Only `java.*`, `javax.*` and the JDK's own `com.sun.net.httpserver`. The UI page
is copied into the jar, so the binary is genuinely self-contained — students
need a JRE and the one file.

Verify a build before handing it out:

```bash
java -jar dist/xchg-server.jar --selftest    # CRC against the course vectors
java -jar dist/xchg-server.jar --vectors     # what students will be matching
```

The server refuses to start if the CRC self-test fails.

## What to hand out

| give them | keep |
|---|---|
| `dist/xchg-server.jar` | `src/`, `build.sh`, `resources/` |
| `../PROTOCOL.md`, `../README.md` | |

No client exists anywhere in the kit, so there is nothing to leak.

## Source map

| file | what it is |
|---|---|
| `Crc16.java` | CRC-16/CCITT-FALSE + the course check values |
| `Packet.java` | the XCHG/1 envelope: constants, encode, decode, error codes |
| `Exchange.java` | price-time-priority limit order book, matching, market maker |
| `Server.java` | UDP receive loop, soft sessions, impairment, packet log |
| `WebUi.java` | `com.sun.net.httpserver` + the `/api/state` JSON snapshot |
| `Main.java` | CLI, `--vectors`, `--decode`, `--selftest` |
| `resources/ui/index.html` | the exchange UI, vanilla JS, no CDN |

`--vectors` is generated by the same encoder the server runs on, so the
published vectors cannot drift from the implementation. If you change the wire
format, the vectors change with it — regenerate `PROTOCOL.md`'s worked example
from the new output.

## Running it for a class

```bash
java -jar xchg-server.jar --udp-port 9001 --web-port 9000
```

Sessions are keyed by source address and port, so a whole lab can share one
instance and trade against each other; the UI attributes every trade to a team.
Rate limiting (200 pkt/s/session) and a 64-order resting cap keep one runaway
loop from spoiling it. Put the UI on a projector — the packet log answers most
questions before they are asked.

For a single student working alone, the built-in market maker means the book is
never empty. `--no-mm` turns it off if you want them to face an empty book.

## Options worth knowing

| flag | effect |
|---|---|
| `--loss P --dup P --delay MS` | impair the link; `--seed N` makes a run reproducible |
| `--no-mm`, `--mm-spread`, `--mm-size`, `--mm-interval` | tune or remove the market maker |
| `--verbose` | print every packet to stdout as well as the UI |
| `--no-web` | headless, for a machine with no browser |
| `--log-size N` | packet log depth (default 400) |

## Extending it

The pieces a later phase will want are already separated: `Packet` knows the
envelope and nothing about markets, `Exchange` knows markets and nothing about
sockets, and `Server` is the only thing that touches `DatagramSocket`. Phase 2's
R-UDP sits between `Server` and `Packet` without either of the other two
changing.
